# PCB and Gerber guide (PS-7 point 7)

The Gerber file has to come from a real PCB layout, so this part is yours to do in KiCad 8
(or EasyEDA). Below is everything needed so it matches the firmware pin map.

## 1. Schematic (net list)
| Net | From | To |
|---|---|---|
| +5V | USB / VIN header | MQ-3 VCC, relay VCC, LCD VCC, ESP32 VIN |
| +3V3 | ESP32 3V3 | pull-ups only if needed |
| GND | all grounds | common |
| MQ3_AO_RAW | MQ-3 AO | R1 10k (top) |
| MQ3_AO | R1 / R2 junction | ESP32 GPIO34 |
| (R2) | MQ3_AO | GND via 15k |
| BTN | push button | GPIO32 and GND |
| LED_G | GPIO26 | 220R -> green LED -> GND |
| LED_R | GPIO27 | 220R -> red LED -> GND |
| BUZ | GPIO25 | buzzer (+), buzzer (-) to GND |
| RELAY_IN | GPIO33 | relay module IN |
| SDA / SCL | GPIO21 / GPIO22 | LCD I2C header |

Add 100 nF across each module supply and 10 uF at the 5 V entry. Add a 1N4007 across any motor load.

## 3. Assembly requirements (found during review, 2026-11-22)

- **Relay input pull-down (required):** fit a 10 kΩ resistor between the relay module IN pin and GND (or use an active-low relay module). GPIO33 is high-impedance during reset/boot, so without it the relay input floats before the firmware drives it low.
- **LCD I2C voltage (required):** do NOT connect a 5 V LCD I2C backpack directly to GPIO21/22. Use a bidirectional I2C level shifter, or a backpack whose pull-ups go to 3.3 V. Many 1602 backpacks pull SDA/SCL up to their 5 V supply, which can damage the ESP32.
- **Buzzer drive:** check the active buzzer's current draw against what GPIO25 can safely supply. If it needs more, drive it through a transistor / MOSFET instead of directly from the pin.
- **Hand-built Gerbers:** the submitted Gerber set in `gerber/` was generated by `make_gerber.py` (hand-written Python), not in KiCad — see `gerber/VERIFICATION.md` for its checks and limits. If you redo the layout in KiCad, keep the net list above and run ERC/DRC to zero errors.

## 4. Steps in KiCad
1. New project. Draw the schematic with the nets above. Use pin-header footprints for the
   ESP32 DevKit (2 x 19 sockets), MQ-3 module, LCD, relay module, buzzer, button.
   **Header order is the Espressif DevKitC V4 order** (left J1 top to bottom:
   3V3, EN, VP36, VN39, D34, D35, D32, D33, D25, D26, D27, D14, D12, GND, D13,
   D9, D10, D11, VIN; right J3 top to bottom: GND, D23, D22, TX0, RX0, D21, GND,
   D19, D18, D5, TX2, RX2, D4, D0, D2, D15, D8, D7, D6) — the first revision of
   the hand-built Gerbers had the right header shifted by one position, which
   put +5V on a GND pin and SDA/SCL on the wrong pins; it is fixed in
   gerber/VERIFICATION.md. Verify the order against your physical board
   before ordering — DevKit clones vary.
2. Run ERC until zero errors. Assign footprints (Tools > Assign Footprints).
3. Open the PCB editor. Set 2 layers, board outline on Edge.Cuts about 80 x 60 mm, 4 x M3 holes.
4. Design rules: 0.25 mm signal tracks, 0.5 mm or more for 5 V and GND, 0.2 mm clearance
   (check your fab's minimums). Place the MQ-3 at an edge, away from heat sources.
5. Route, add GND zones on both layers, stitch with vias. Add silkscreen: references, pin names, polarity, project name and version.
6. Run DRC until zero errors.
7. File > Fabrication Outputs > Gerbers. Select F.Cu, B.Cu, F.Mask, B.Mask, F.Silkscreen, B.Silkscreen, Edge.Cuts. Then Generate Drill Files (.drl).
8. Zip all Gerber and drill files into gerber/gerber.zip.
9. Open the zip in KiCad's Gerber viewer (or any online viewer) and check outline, drills and silkscreen.
10. Take a screenshot of the PCB and of the 3D view for the report (optional bonus).
